```
                    ┌──────────────── 浏览器（无构建，原生 JS） ───────────────┐
                    │  MJPEG 画面 │ 俯视图 │ 现场事件流 │ D-pad │ 设置抽屉      │
                    └───────▲─────────────▲──────────▲───────────────────────┘
                            │             │          │ SSE
┌───────────────────────────┼─────────────┼──────────┼───────────────────────┐
│ FastAPI (uvicorn, 单进程)  │             │          │                       │
│                            │             │          │                       │
│  capture.Camera ──帧──► loop._tick ──► brain.decide ──► safety ──► driver   │
│   （线程，只留最新帧）      │              │  ↑           │          │        │
│                            │              │  │           │          │        │
│  capture.AudioCapture ─────┼─► VAD ─► ASR ─┘  │           │          │        │
│   （线程，16k 单声道）      │                 │           │          │        │
```

## 一次决策经过什么

以"往前走一点"为例，主机内部的时间线（实测）：

| 时刻 | 发生什么 | 耗时 |
| --- | --- | --- |
| t+0ms | 网页 `POST /api/chat` → 入队一句话，**立刻返回** | <5ms |
| t+1ms | 主循环（250ms 一跳）取到这句话，抓当前帧 | ~1ms |
| t+5ms | 组提示词：画面 + 身体状态 + 最近 3 句话 + 最近 3 个动作 | ~2ms |
| t+7ms | `POST /v1/chat/completions`（图片 + JSON 模式 + 关思考链） | — |
| t+1200ms | 模型返回 `{"action":"forward","speed":0.2,...}` | ~1.1~1.3s |
| t+1202ms | `parse_json` → `normalize` → `SafetyGate.check` | <1ms |
| t+1203ms | 反射层：正前方 1.40m > 0.25m，放行 | <1ms |
| t+1204ms | `driver.execute` **立刻返回**，运动在后台自己收尾 | <5ms |
| t+2004ms | 动作到时，驱动自己停；`action` 事件推给网页 | — |

关键设计：**`execute()` 绝不阻塞**。如果驱动同步睡 800ms，主循环就废了 ——
这段时间里来了急停也执行不了。所有驱动都是"发出去就返回，自己计时自己停"。

## 模块

| 文件 | 职责 | 为什么单独存在 |
| --- | --- | --- |
| `app/config.py` | `.env` + `data/settings.json`，热更新，Key 掩码 | 用户改配置不该重启进程 |
| `app/actions.py` | 7 个动作、别名归一、JSON 容错解析、规则预判 | 模型输出必须先"收敛"才能执行 |
| `app/safety.py` | 急停锁存、限速限时、频率限制、能力检查、看门狗 | 唯一有否决权的地方 |
| `app/llm.py` | OpenAI 兼容客户端 + 参数降级 + 空回复重试 | 各家的坑不一样，得会退让 |
| `app/vision.py` | 9 键画面描述 + 磁盘缓存 | "看懂"比"决策"贵，要能复用 |
| `app/asr.py` | VAD + mock/local/cloud 三种识别器 + 唤醒词 | 没麦克风也能演示 |
| `app/brain.py` | 提示词 + 决策 + 理解 | 项目的"人格"在这 |
| `app/loop.py` | 主循环、事件总线、数据录制 | 把所有零件接起来 |
| `app/sim.py` | 光线投射模拟器 + 运动学 | 没硬件也能端到端验证 |
| `app/drivers/` | mock / ir / button / serial / none | 换身体只改一个字符串 |
| `app/server.py` | HTTP + SSE + MJPEG | 前端只有一个页面 |
| `web/` | 驾驶舱界面，原生 JS，无构建 | 克隆下来就能跑，不需要 npm |

## 三条"反直觉"的取舍

**1. 不做视频流，做 MJPEG。**
`multipart/x-mixed-replace` 在 2026 年依然是最省事的方案：浏览器原生支持、零依赖、
延迟比 HLS 低。代价是每个客户端一条 TCP 连接 —— 单机驾驶舱完全够用。

**2. 不让前端打造型，让后端出 JSON。**
`/api/state` 是一个自洽的快照，网页只管画。这样脚本、curl、别的 UI 都能接。

**3. 决策间隔 1.8 秒，而不是"能多快就多快"。**
连续决策的收益很小（画面几乎没变），成本是 token 和抖动。1.8 秒意味着
"人说完话 → 机器人动"大约 1.2 秒，然后留给动作 0.6~2.5 秒 —— 节奏像人。

## 失败会怎样

| 故障 | 现象 | 兜底 |
| --- | --- | --- |
| LLM 超时 / 401 | 决策卡显示错误 | 返回 `stop`，网页提示；不影响其他功能 |
| 模型输出不是 JSON | 日志有 `输出解析失败` | 同上，`stop` |
| 模型想违章（速度 1.0） | 被夹到 `max_speed` | 静默降级，`why` 里看得到 |
| 画面过期（>3s） | 自动模式下拒绝移动 | 走 `stale_frame` 分支，不调模型 |
| 摄像头掉线 | 顶栏"眼"变红，画面停 | 保留最后一帧，决策降级为纯语音 |
| 遥控器桥断线 | 顶栏"身体"变红 | 自动重连（1s→8s 退避）；重连后**不重放**旧动作 |
| 主循环卡死 | 看门狗 | 只在"正在动"时触发，静止不刷日志 |
| 急停 | 红色横幅 + 所有动作变 stop | 锁存，必须手动解除 |

## 数据录制

`record_episodes`（默认开）会在 `data/episodes/<时间戳>/` 下留：

```
episode.jsonl     每行：{t, frame_seq, state, action, result}
frames/00012.jpg  决策时的那一帧（节流，默认每 1.5 秒最多一张）
meta.json         {started, driver, model, camera}
```

这才是这个项目真正的长期价值：**"画面 → 决策 → 动作 → 结果"的配对数据**。
攒够几千条，就能拿去做行为克隆（VLA 微调），而不是永远停在提示词工程。
