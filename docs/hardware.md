# 硬件：让一台现成的机器人听程序的话

这个项目最难的部分不是大模型，是**最后 30 厘米** —— 模型说"往前走"，
怎么让一堆塑料轮子真的转起来。

按"改动从小到大"排，有五条路。先看表，再看细节。

| # | 方案 | 要不要拆机 | 花钱 | 上手时间 | 通用性 | 推荐度 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `DRIVER=mock` 模拟身体 | 不用 | 0 | 0 | — | ★★★★★ 先跑通 |
| 2 | 红外学习回放 `DRIVER=ir` | 不用 | ~30 元 | 30 分钟 | 红外遥控的都能用 | ★★★★★ |
| 3 | 舵机压真按键 `DRIVER=button` | 不拆，但要个架子 | ~50 元 | 1~2 小时 | 任何遥控器 | ★★★☆☆ |
| 4 | GPIO 直连按键矩阵 | 要拆遥控器 | ~10 元 | 半天 | 薄膜/矩阵键盘 | ★★☆☆☆ |
| 5 | 串口直驱电机 `DRIVER=serial` | 要拆机器人 | ~40 元 | 半天 | 自己搭的底盘 | ★★★★☆ |

> 结论：**先用 1 跑通，再用 2 接真机**。方案 2 覆盖了市面上绝大多数玩具机器人，
> 而且完全可逆 —— 拔掉线，机器人还是原来那台机器人。

## 方案 1：模拟身体（先跑通闭环）

什么都没有也能玩。`DRIVER=mock` 时，画面、测距、位姿全来自内置的 2D 光线投射模拟器
（`app/sim.py`），有墙、有走廊、有一个站在你正前方的"路人"、有一个红杯子、有一块门牌。

```bash
python serve.py     # 打开 http://127.0.0.1:8790
```

你会看到第一人称画面、俯视图、正前方距离。说一句"往前走一点"，它真的会走。
这一步的目的是**把 LLM 延迟、安全层、前端全部验证完**，再去动螺丝刀。

---

## 方案 2：红外学习回放（推荐）

玩具机器人 90% 用红外遥控：38kHz 载波，NEC / SONY / SAMSUNG / RC5 协议居多。

**原理**：ESP32 用红外接收头把遥控器的码"听"下来（`code + protocol + bits`），
存到主机；之后主机让 ESP32 用红外 LED 把这个码原样发出去。**不需要知道协议细节。**

- 学：`ir_learn` → 收到 `ir_learned{code, protocol, bits}`
- 发：`ir_send{code, protocol, bits, repeat}`

红外是一次性协议，按住不放 = 反复发同一个码。所以"往前走 800ms"会被翻译成
`repeat≈6`（间隔 120ms），时长到了再补一帧 `stop`。这就是 `app/drivers/remote.py`
里 `RemoteDriver` 干的事。

**用料**

| 件 | 单价 | 备注 |
| --- | --- | --- |
| ESP32 DevKit | ~15 元 | 有 Wi-Fi，主机不用拉线 |
| VS1838B 接收头 | ~1 元 | 38kHz，低电平有效 |
| 940nm 红外发射 LED | ~0.5 元 | 建议 2 只并联 + S8050 三极管 |
| 100Ω 电阻 | ~0.1 元 | 限流 |

接线和烧录见 [`firmware/README.md`](../firmware/README.md)。

**注意事项**

1. 发射 LED 尽量贴着机器人的接收窗，正对，距离 5cm 内最稳。
2. 学码时关掉日光灯/LED 灯（有些灯有 38kHz 频闪，会干扰）。
3. 同一个遥控器上"前进"和"后退"的码可能只差一位 —— 学完一定要在网页里逐个点一遍验证。
4. 长按和短按可能发不同的码（有些遥控器长按会发 repeat 帧），必要时给动作留 `hold_ms`。

参考资料：
[IRremoteESP8266](https://github.com/crankyoldgit/IRremoteESP8266)（协议解码的事实标准）、
[ESP32 RMT 文档](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/rmt.html)
（RMT 是 ESP32 的硬件脉冲发生器，发红外不占用 CPU）。

## 方案 3：舵机压真按键（万能，但笨）

遥控器是 2.4G / 蓝牙 / 私有协议，红外那套用不了怎么办？
**别碰协议，直接上手按。** 3D 打印一个架子，把 4 个 SG90 架在方向键上方，
程序让舵机动一下，等于你按了一下。

- 优点：**任何**遥控器都能用，不改电路、不逆向、不改固件。
- 缺点：慢（一次按键 100~200ms）、吵、丑、会磨损遥控器按键。
- 适合：验证阶段、遥控器只有几个键、你不想动电烙铁。

主机侧 `DRIVER=button`，`press` 动作带 `servo` 编号。学习过程就是
`servo_test` 一个个试，试到哪个键能动就记下来 —— 见 `data/ir_codes.json` 里
`{"slot":"forward","servo":0}` 这种记录。

> 别用金属舵机臂直接压薄膜按键，会压穿。贴一小块硅胶/热熔胶做缓冲。

## 方案 4：GPIO 直连按键矩阵

拆开遥控器，找到按键矩阵的行列线，用 ESP32 的 GPIO 直接拉低对应行列 —— 
等价于按下那个键。成本最低（几根线），但**要拆遥控器**，而且每个型号的矩阵都不一样。

已知的开源参考：
[YanWittmann/esp32-button-matrix-remote](https://github.com/YanWittmann/esp32-button-matrix-remote)。

风险：拆坏了就没了；有些遥控器的按键是模拟电压分压（一根 ADC 线读多个键），
那就得用 DAC 或电阻网络去模拟电压，更麻烦。**不建议作为第一方案。**

## 方案 5：拆掉遥控器，直接驱动电机

如果你愿意把机器人打开，看到里面是 L298N / TB6612 / DRV8833 这类电机驱动板，
那就别绕弯了：主机用串口直接给左右轮 PWM。

- 接线、固件见 [`firmware/arduino_motor_serial`](../firmware/arduino_motor_serial/arduino_motor_serial.ino)
- 主机侧 `DRIVER=serial`，`driver_serial_port=COM3`
- 好处：延迟最低（<20ms）、可以读编码器、可以做真正的速度闭环
- 代价：原来的遥控器就废了（除非保留一个切换开关）

**别做的事：逆向 2.4G 私有协议。** 技术上可行（nRF24 抓包 +
[puskyer/NRF24_Sniffer](https://github.com/puskyer/NRF24_Sniffer)），
但一个遥控器一套协议，换个型号全部重来，投入产出比极差。
真到了这一步，方案 3 的舵机更省时间。

## 安全：三层，缺一不可

```
大模型（会犯错）
   ↓  ①提示词：只给 7 个动作、一次一小步、先看再走
SafetyGate（不会心软）
   ↓  ②限速 / 限时 / 频率限制 / 急停锁存 / 能力检查 / 防撞反射 / 看门狗
固件（最后的底线）
   ↓  ③命令超时自动停 / 断线松开 / 超声波太近拒绝前进
电机
```

| 层 | 拦什么 | 代码 |
| --- | --- | --- |
| 提示词 | 让模型"想得起停" | `app/brain.py` |
| 安全层 | 让模型"停得住"：speed≤0.6、单次≤2.5s、间隔≥250ms、正前方<0.25m 拒绝前进 | `app/safety.py` |
| 固件 | 上位机挂了也不跑飞：1~2 秒没命令自动停 | `firmware/` |

**第一次上真机，务必：**

1. 把轮子架空（垫本书），确认方向对、不会突然满速；
2. `max_speed` 先设 0.3，`max_duration_ms` 设 800；
3. 手放在急停按钮上（网页右上角红色按钮，或直接拔电）；
4. 先 `mode=idle` 用文字遥控，确认每一个动作都对，再开自动巡逻。

## 这台机器人的"感官"怎么接

| 感官 | 现在 | 换真硬件 |
| --- | --- | --- |
| 眼睛 | 模拟器渲染 | `CAMERA_SOURCE=opencv` + USB 摄像头（`CAMERA_INDEX=0`），或 `file` 循环播一段视频 |
| 耳朵 | 模拟对话 | `AUDIO_SOURCE=mic` + `ASR_PROVIDER=local`（faster-whisper，本机免费）或 `cloud` |
| 距离 | 模拟器光线投射 | 方案 5 的超声波（`front_cm`）；红外/舵机方案没有距离，会退化成"只看画面" |
| 电量 | 模拟 | 方案 5 的 `battery` 字段，或自己从驱动板读 |

> 用红外方案时**没有测距**，防撞反射层就没数据可用了。这时候唯一的防线是
> VLM 自己看出"前面有东西" + 限速 + 限时。所以红外方案请把 `max_speed` 调到 0.3 以下。
